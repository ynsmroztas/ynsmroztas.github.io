AndroScope

A rootless Android pentest framework. Not a spy in the status bar.

What it is Why gadget Pipeline Static engine Radar Runtime Arsenal What it is not vs AndroHunter

What it is

AndroScope is the mobile research bench I built after years of hunting on Android without wanting a rooted daily driver. The public pitch is simple: patch an authorized lab APK once, load a Frida Gadget into that package, then run a full PREPARE → ASSESS → RUNTIME loop on a real, unrooted phone.

The important sentence is the second one. AndroScope does not attach to a random Play Store process from the outside. Android will not let a normal third-party app walk into another app’s address space. The runtime lives inside the target you were allowed to instrument. You open that target. You tap through login, WebView, pay, share, deeplink. The session log is a transcript of your gestures, not a ghost service.

Design rule: instrument the target. Do not pretend a second APK can police every other APK in the background. That story is not how the platform works, and I will not sell it.

Why Gadget, not “Frida server on a rooted lab”

Most public Android labs assume Magisk + frida-server + USB. That is fine for an emulator farm. It is a poor model for bug bounty phones that stay on a carrier network, stay unrooted, and still need to exercise Play Integrity adjacent flows.

Gadget is Frida’s in-process library. The dynamic linker runs its constructor when the lab build starts. From that moment the operator console can load modules, pause at first frame (wait) or let the app run and race (resume), and regenerate JS without packing the APK again.

I am not publishing a packing cookbook here. The point of this page is the operator model and the analysis surface — not a recipe for shipping someone else’s package with a foreign .so.

The pipeline

StageInputOutput
PREPAREAPK bytesPackage identity, SDK floor, components, schemas, DEX strings, signing block
ASSESSSurface + rulesFH-ID findings, confidence, MASVS-shaped notes, a plan
RUNTIMELab build + operatorVerified events while the target is actually used

Each finding is hashed into a stable FH-ID so a report can say “FH-7A91, exported editor activity, MEDIUM” instead of pasting a screenshot of a dashboard. Plans are generated from the surface that exists — if there is no FileProvider, there is no FileProvider step.

Static engine

PREPARE is boring on purpose. Binary XML in AndroidManifest.xml is not text. AndroScope walks ResChunk headers, the string pool (UTF-8 and UTF-16), the resource map, and typed values: strings, booleans, ints, resource refs. From that it reads exported flags, allowBackup, minSdkVersion / targetSdkVersion, providers, intent-filters, and deeplink hosts.

DEX is treated as a string table first. MUTF-8 entries from string_ids are scanned for URL shapes, key-shaped literals, and a small secret grammar. It is not decompiler theater. If a string is not in the table, AndroScope does not invent it.

The APK signing block is detected (v2 / v3 magic) so the report can say “v1 + v2” instead of “probably signed.” Nested APKs (plugins, instant modules) are copied out of the zip into a fresh buffer before parse — no shared-buffer tricks.

What “surface” means here

  • Activities / services / receivers / providers with exported state and intent-filters.
  • Deeplinks as scheme + host + pathPrefix, not a single “has deeplinks: yes” bit.
  • Permissions as declared vs used, with a short dangerous set highlighted.
  • WebView / JS bridge only when the binary actually references those APIs.
  • Native as present .so ABIs, not a fake disassembly pane.

Radar and honesty

Early drafts of the UI lied. A lab sample with one exported activity was painted CRITICAL. That is how you train hunters to file junk. The scoring I use now is conservative:

  • A single exported activity on a notes app → MEDIUM, not HIGH.
  • allowBackup=true on modern targetSdk → MEDIUM with context, not “data exfil guaranteed.”
  • Old targetSdk → LOW or MEDIUM depending on the rest of the surface.
  • Hardcoded secrets in DEX → HIGH only when the pattern plus entropy plus usage context agree.

Radar then chains what exists. Exported provider + open path + backup is a path. Exported provider alone is a finding. The difference matters when you write for Apple, Meta, or a private program that has seen a thousand “exported=true” reports.

How a live test actually feels

This is the question I get most: “I install AndroScope, I open WhatsApp, AndroScope watches in the background — right?”

No.

Authorized workflow:

  1. You have the APK you are allowed to test (your build, the program’s lab build, a package in scope).
  2. PREPARE / ASSESS run on that file. Surface and plan exist before any hook fires.
  3. A lab variant of that package is instrumented. The original store build stays untouched.
  4. You launch the lab variant. wait holds the first frame until modules attach. resume lets the app run; you accept the race.
  5. You use the app the way a user would. Deeplink from Notes. Open the in-app browser. Hit pay. Background and restore.
  6. The console prints verified lines only when the corresponding API actually ran. Empty log means you did not hit the surface, not that the surface is safe.
  7. You export evidence. You uninstall the lab variant. You do not leave an instrumented package on a daily phone.

The “background” feeling is real in one sense only: once the gadget is inside the target, you can put AndroScope’s console aside and use the target with both thumbs. The process doing the work is still the target process.

Arsenal, grouped by surface

The July 2026 public thread listed 38+ modules. They are grouped so a plan can pick a shelf instead of dumping every script into every session.

Defense

TLS pinning variants, RASP heartbeats, Play Integrity client calls, biometric gates, Cronet.

Traffic & secrets

HTTP / WS intercept, token and crypto dumpers, gRPC and protobuf, keystore and shared prefs.

IPC

Live intent capture and replay, schema-aware deeplink fuzz, provider and confused-deputy probes.

Native

.so tracer, memory sweep for high-entropy blobs, interaction tracer for UI-driven native calls.

Niche

Lottie zip paths, PDF.js / Cordova LFI-shaped loads, OAuth PKCE, React Native bridge and storage.

Regen

Rebuild the JS toolkit for the same gadget without packing the APK a second time.

Modules that do not match the surface stay dark. A pure Compose app without a WebView does not get a WebView chapter in the report. That is the whole point of PREPARE.

What AndroScope is not

  • Not a Play Store product that silently hooks whatever you open.
  • Not a replacement for AndroHunter. Hunter is the on-device Swiss army knife. Scope is the session framework.
  • Not a guarantee that Integrity / RASP / pinning will fall on every target. Those are observations plus fallbacks, scored honestly.
  • Not a dump of 0-days. The July note mentioned Android 0-days under research, with sandbox escape as the interesting direction. They are not part of this writeup.

Status

AndroScope is being opened in limited form. The static auditor and the operator UI are the public face. The packer and the full module pack stay in the private tree until I am done cutting anything that looks like a general-purpose injector.

If you are on a private program and you already work with me, you get the session build. If you found this page from the site, you get the model, the scoring rules, and the distinction I wish more tool landing pages would print in the first screen.
