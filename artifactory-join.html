WRITEUP · PLATFORM · AUTH · CVE-2026-82329 · @YNSMROZTAS

Empty join key, admin token

● liveclk --:--:--CWE-287

Self-hosted Artifactory trusted a blank cluster join key. That default is the finding. This page does not mint tokens.

CVE-2026-82329Artifactoryself-hostedauth bypass

The class

Access, on a default self-hosted box, treated an empty join key as a valid cluster secret. A known empty secret is not a secret. Anything signed under that default can be accepted as a peer. The impact class is an unauthenticated platform administrator session — configuration, users, tokens, repositories — not “a local account appeared.”

Cloud-hosted Artifactory is out of scope. Self-hosted branches in the 7.111–7.161 lines were the surface. Vendor builds that reject the empty key close the class.

What this page will not do

  • No join-endpoint walkthrough.
  • No signing-key derivation.
  • No token exchange, no admin-create flag, no recon query.
  • Persistence (“a user exists after”) is a follow-on, not the root finding.
Report the class as unauthenticated administrator token acquisition on a default self-hosted Access node. Patch first. Then rotate the join key so empty is rejected.

Affected lines (vendor advisory)

Vulnerable bands sat under 7.111.20, 7.117.27, 7.125.19, 7.133.28, 7.146.37, 7.161.19. Fixed counterparts start at the next build on each line; 7.191.14 is the later unified floor. Confirm on the box you own. Do not scan third-party hosts.

Fix

  • Upgrade to a fixed self-hosted build before you argue about keys.
  • Set a join key that is not empty. Restart Access so the old default is dead.
  • Rotate tokens issued while the box was on a vulnerable build.
  • If the instance was on the public internet, treat it as compromised until logs say otherwise.
