Password in the query string

Summary

Lab package com.labnet.console (build 4.x, React Native) sent the login as POST — but put email and the plaintext password in the query string, not the body. TLS was on. That is not the bug. The bug is that a high-value secret was placed in the one field every proxy, WAF, access log, and error SDK treats as safe metadata.

AndroScope watched the in-process React Native bridge while the operator tapped Sign in. The same full URL showed up in two other modules in that session: the error-monitoring SDK breadcrumb, and the cookie helper. Vendor names from the original program are not on this page.

Class: secret in URL query. Transport: TLS. Consumers: first-party request logs + third-party error SDK. Fix: move fields into the POST body.

Why the URL is the wrong place

The request already declared Content-Type: application/json. The body was available and unused for these fields. Query strings are copied into access logs, load-balancer traces, WAF events, and — here — an HTTP breadcrumb the error SDK later ships with any event.

AndroScope did not need a proxy or a broken TLS stack. The values existed on the RN bridge before the socket. Empty log would have meant the operator never hit login. This log is the opposite.

Two consumers in one session

  1. Error-monitoring SDK. Breadcrumb url was the raw login URL, password included. Whether a server-side scrubber later deletes it is a control on one consumer. It does not fix first-party request logs.
  2. Cookie helper. The same URL was passed into a module that has no reason to see a password.

This page does not name the SDK project, ingest host, or hook the vendor’s production org. That stays in the private report.

Impact (class)

Anyone who can read URL logs — on the vendor side or inside the error project — can read the password of any user whose session produced a recorded request. Dashboard-class accounts often administer network gear. Treat the secret as high, even though the path is “just logging.”

Fix

  • Move email, password, and remember_user into the POST body.
  • After that, the breadcrumb and cookie helper stop inheriting the secret for free.
  • Defence in depth: scrub the login path in the error SDK, and purge historical URL logs that already stored the parameter.
